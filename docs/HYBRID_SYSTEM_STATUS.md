# ORION SSA Hybrid System Status

Updated: 2026-10-11

## Architecture

ORION keeps physical trajectory assessment, learned event-risk inference, and catalog heuristics as independent outputs. Stage 2A propagates accepted live or fallback TLE inputs with SGP4/SDP4, WGS-72, and TEME, then reports sampled candidate pairs and refined closest approaches. The trained ESA model consumes only nine event-level geometry/time features extracted from an eligible Stage 2A event. It never changes the physical result. Foster 2D Pc is a separate output requiring valid same-epoch covariance and sourced hard-body radii. `comparison_result` reports `not_comparable` when ESA log-risk and physical Pc/geometry are both present; it does not claim agreement.

## Screening sharing and cache identity

The in-memory screening key includes sorted TLE input hashes, source types/groups/timestamps and element epochs, catalog source generation/status, catalog limit, exact UTC screening start, horizon, sampling interval, threshold, candidate/refinement/sample caps, TCA refinement tolerances, relative-speed bound, WGS-72, SGP4 version, method version, and ESA artifact identity. The result cache expires after 30 seconds. Inputs with a different catalog identity, generation, horizon, start, model, or configuration cannot receive the cached result. Job polling reads one submitted job and never starts another screen. Orbital physics, sample step, threshold, candidate limits, and refinement behavior remain unchanged.

In the local environment, a prior 900-object catalog call took 21.0 seconds; building 120 heuristic proxies took 71.8 seconds. A prior 900-object, 24-hour conjunction request did not return within a 240-second client timeout, so that run terminal status and stage timings remain unmeasured. A separate live 900-object, 0.1-hour run completed with 884 usable tracks, 7 epochs, 2,419 candidate pairs, 2,424 refinements, 18 events and no candidate cap. It took 5.530 s for Stage 2A and 6.130 s for the API request; refinement took 2.035 s, ML inference 2.312 s, and neighbor comparisons 0.899 s. These timings identify refinement and per-event ML inference as the largest measured stages for that short run; they do not prove which stage dominated the earlier 24-hour timeout. In a separate run using the modified server while upstream network access was unavailable, the explicit fallback contained 7 objects and the 0.1-hour, 7-epoch screen completed valid-empty in 0.014 s Stage 2A / 0.027 s API time. This fallback result is not comparable to the live 900-object timing. The default 60-second step samples 1,441 epochs over 24 hours. The cache prevents repeat work for identical inputs; it does not make a first-time full screen faster.

## Data and interpretation

- ESA model target: final event `log10` historical risk selected from the ESA Collision Avoidance Challenge event sequence. The exponentiated display is not collision probability.
- ESA inference requires a valid Stage 2A event with all nine feature values and consistent TEME state/time. Missing or unsupported features return an unavailable reason; no features are imputed.
- Pc requires validated covariance and hard-body radius inputs with compatible frame/epoch. Missing inputs remain unavailable, never zero.
- Catalog heuristics and proxy pairs are deterministic review aids only. Offline demo/synthetic provenance remains explicit and is not included in physical screening.
- A candidate cap, invalid input, or propagation error marks the trajectory search partial. Partial results do not claim complete coverage.
